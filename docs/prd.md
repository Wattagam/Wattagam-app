## 2. 제품 정의와 목표

왔다감은 정문 느티나무길, 중앙도서관, 호수정원, 학생회관을 걸으며 GPS로 방문을 확인하고, 푸앙이와 찍은 사진에 손그림·글을 더해 공개 방명록으로 남기는 Android 앱이다. 방명록을 남긴 장소마다 도장이 찍힌다.

### 2.1 해결하려는 문제

| 사용자 문제 | 제품의 대응 |
| --- | --- |
| 신입생과 방문객이 캠퍼스 주요 장소에 익숙하지 않다. | 지도와 장소 설명, 찾아가는 길로 4개 장소를 안내한다. |
| 장소에 쌓인 다른 사람의 기록을 보기 어렵다. | 장소 갤러리에서 공개 기록을 위치 권한 없이 열람한다. |
| 장소 방문을 추억으로 남길 수단이 부족하다. | 푸앙이와 함께 찍은 사진에 손그림·글을 더해 기록한다. |
| 어디에 기록을 남겼는지 기억하기 어렵다. | 방명록 저장 성공 시 장소별 도장을 지급하고 마이페이지에서 모아 본다. |

### 2.2 MVP 목표

1. 카카오 로그인과 닉네임 설정 후 4개 장소를 지도와 목록에서 확인한다.
2. GPS로 현장 방문을 확인하고, 현장에서만 방명록을 작성한다.
3. 지원 실기기에서 푸앙이가 포함된 AR 사진을 찍고, 미지원 기기에서는 일반 사진으로 같은 흐름을 완료한다.
4. 방명록을 전체 공개로 올리고, 저장 성공 후 해당 장소의 도장을 받는다.
5. 마이페이지에서 도장과 내 기록을 확인하고, 내 기록을 수정·삭제한다.
6. 재실행·재로그인 후에도 방명록, 도장이 유지된다.

### 2.3 완료 수준

- P0: 카카오 로그인·닉네임, 4개 장소, GPS 방문 확인, 일반 사진 기반 작성·공개 업로드, 공개 갤러리, 도장, 마이페이지 도장판.
- P1: AR 촬영 통합, 내 기록 수정·삭제, 닉네임 수정, 회원 탈퇴.
- 목표 MVP는 P0와 P1을 모두 포함한다. AR을 일반 촬영으로 대체했다면 AR 촬영 완료로 보고하지 않는다.
- 앱 스토어 배포 시 앱 내 계정 삭제 경로가 요구될 수 있으므로, 배포 계획이 있으면 회원 탈퇴를 P0로 올린다.

## 4. 장소와 핵심 정책

### 4.1 고정 투어 장소

코스명은 '푸른캠퍼스 산책'이다. 지도와 목록은 아래 순서로 보여주되 방문 순서는 강제하지 않는다. 사용자는 어느 장소의 설명에서든 시작할 수 있다.

| 순서 | 장소 | 방문 확인 지점 | 관람 포인트 |
| --- | --- | --- | --- |
| 1 | 정문 느티나무길 | 정문 느티나무길 (정문 안내석에서 안쪽으로 30m, 첫 번째 벤치 옆) | 고개를 들면 만나는 초록빛 나무 터널 |
| 2 | 중앙도서관 | 중앙도서관 앞 계단 | 계단에서 바라보는 창가의 빛과 그림자 |
| 3 | 호수정원 | 호수정원 나무 데크 | 데크 끝에서 만나는 호수의 반영 |
| 4 | 학생회관 | 학생회관 정문 앞 광장 | 광장 벤치와 다채로운 동아리 게시판 |

장소별 기준 좌표, 방문 반경은 현장에서 확정하고, 대표 사진은 앱에 포함한다.

### 4.2 서로 다른 판정의 구분

| 판정 | 조건 | 결과 |
| --- | --- | --- |
| 방문 확인 | 유효한 현재 GPS가 장소의 방문 반경 안에 있음 | 현장 작성 자격(저장하지 않음) |
| 도장 지급 | GPS 조건을 충족한 방명록이 서버에 저장 완료됨 | 장소별 도장 1개 |

방문 반경은 기존 30m를 임시로 유지하고, 현장 테스트 후 장소별로 확정한다. 방문 확인이나 AR 촬영만으로는 도장을 지급하지 않는다.

### 4.3 위치와 공개 정책

- 장소 설명과 공개 갤러리는 위치 권한 없이 열람할 수 있다. 장소를 선택하는 것만으로 방문을 인정하거나 작성 잠금을 해제하지 않는다.
- 방명록 작성 시작(04)과 최종 업로드(07)에서 각각 현재 GPS를 확인한다. 과거 방문 기록만으로 현재 작성 권한을 주지 않는다.
- 위치 미확인, 정확도 부족, 반경 밖이면 업로드를 막고, 작성 중인 사진·그림·메시지는 초안으로 유지한다.
- 위치는 앱을 사용하는 동안에만 쓰고, 연속적인 이동 경로는 저장하지 않는다. 백그라운드 위치는 사용하지 않는다.
- 이미지 인식은 쓰지 않는다. AR 평면 인식은 푸앙이 배치에만 쓰고 방문 판정에는 쓰지 않는다.
- 모든 방명록은 로그인한 앱 사용자에게 공개된다. 공개 범위 선택, 나만 보기, 비공개 전환은 없다. 마이페이지의 '내 기록'은 작성자별 모아보기이며 비공개 보관함이 아니다.
- 마이페이지의 '작성 중'은 아직 올리지 않은 초안이다. 공개 기록이 아니고 도장도 주지 않는다.

## 5. 사용자 흐름

화면 번호는 Figma의 번호(01\~09)를 그대로 쓴다.

### 5.1 정상 흐름

1. **01 카카오 로그인.** 신규 계정은 **01-A 닉네임 설정**(2\~10자) 뒤 **01-B 위치 권한 안내**를 거친다. 기존 계정은 바로 지도로 간다.
2. **02 지도.** 4개 핀과 '순서대로 걷기' 목록에서 도장 상태(n/4)를 보고 장소를 고른다.
3. **03 장소 설명.** 소개, 관람 포인트, 찾아가는 길을 읽는다. 공개 기록은 **03-A 장소 갤러리**에서 열람한다. 위치 권한은 필요 없다.
4. **04 GPS 방문 확인.** 방문 반경 안이면 '작성 가능'이 된다. 이 시점에는 도장을 주지 않는다.
5. **05 촬영 방식 선택.** AR(푸앙이와 함께) 또는 일반 사진 중 하나를 고른다. 순차 촬영이 아니다. AR은 **05-A**, 일반은 **05-B**에서 찍는다.
6. **06 사진 확인.** 다시 촬영하거나 갤러리에서 바꿀 수 있다. '사진 꾸미기' 또는 '꾸미지 않고 다음'을 고른다.
7. **06-A 꾸미기(선택).** 손그림과 글자를 얹고 '편집 완료'를 누른다.
8. **07 내용 확인·공개 업로드.** 선택 메시지(0\~80자)를 쓰고, 현재 위치를 다시 확인한 뒤 '공개 업로드'를 누른다.
9. **08 저장 성공·장소 도장.** 새 도장(예: 1/4 → 2/4)을 확인한다. 여기서 내 기록을 수정·삭제하거나 갤러리·마이페이지로 이동할 수 있다.
10. **09 다시 보기.** 장소 갤러리(타인 기록 상세 포함)와 마이페이지(내 기록·도장·설정)는 서로 독립된 목적지다.

방명록이 아직 없는 장소에서도 방문 확인 후 첫 방명록을 쓸 수 있다.

### 5.2 예외 흐름

| 상황 | 동작 |
| --- | --- |
| 카카오 로그인 취소·실패 | 로그인 화면 유지, 재시도 제공, 서비스 세션 미발급 |
| 위치 권한을 '나중에 하기' 또는 거부 | 지도·설명·갤러리는 계속 열람. 지도에 '작성 시 위치 필요' 안내와 '권한 설정' 버튼 표시 |
| GPS 범위 밖·권한 없음 (04-E) | 작성 진입 불가. '현재 위치 다시 확인', '지도로 돌아가기·길 안내 보기' 제공. 작성 중 초안은 유지 |
| AR 미지원·배치 실패 | 일반 사진으로 진행. GPS 작성 조건은 동일 |
| 업로드 실패 (07-E) | '아직 공개되지 않았어요', 도장 미지급, 초안 유지. '위치 확인하고 다시 업로드'는 GPS를 다시 확인한 뒤 게시 |
| 편집 중 장소 이탈 | 편집 내용 유지, 반경으로 돌아오기 전까지 게시 차단 |

## 6. 상세 요구사항과 수용 기준

### FR-01. 카카오 로그인·온보딩

- 로그인 화면에는 '카카오로 시작하기'만 둔다. 자체 가입, 비밀번호, 게스트 이용은 없다.
- 서버가 검증한 카카오 사용자 식별자로 계정을 연결한다. 최초 인증이면 서비스 사용자를 만들고, 이후 서비스 API용 세션(JWT)을 발급한다.
- 신규 계정만 닉네임을 설정한다(01-A). 2\~10자, 한글·영문·숫자. 사용 가능 여부를 즉시 안내한다. 닉네임은 공개 기록에 함께 보이며 설정에서 바꿀 수 있다.
- 닉네임 직후 위치 권한을 안내한다(01-B). '위치 허용하고 지도 열기'와 '나중에 하기 · 지도 둘러보기'를 제공한다. 이미 허용했다면 생략한다.
- 기존 계정은 닉네임·위치 단계를 건너뛰고 지도로 간다.
- 인증이 만료되면 재인증을 안내한다.

수용 기준: 같은 카카오 계정으로 다시 로그인하면 방명록·도장이 복원된다. 인증 실패 시 세션을 만들지 않는다. 가입·비밀번호 입력 화면이 없다. 신규 계정은 닉네임 설정을 마친 뒤 지도로 들어간다.

### FR-02. 지도·장소 목록

- 정문 느티나무길, 중앙도서관, 호수정원, 학생회관 4곳만 표시한다.
- 번호 핀(도장을 받았으면 ✓)과 '순서대로 걷기' 목록(장소명, 길 안내 한 줄, 도장 완료·미수집)은 같은 장소 설명으로 연결한다.
- 상단에 '4개 장소'와 '도장 n/4'를 보여준다.
- 지도는 안내용 약도다. 핀·목록을 고르면 장소 설명이 열린다.
- 위치 권한이 없으면 '작성 시 위치 필요' 안내와 '권한 설정' 버튼을 보여주고, 지도는 계속 쓸 수 있다.

수용 기준: 정확히 4개 장소가 보이고 도장 획득·미수집이 구분된다. 핀을 선택하는 것만으로 방문·작성·도장 상태가 바뀌지 않는다.

### FR-03. GPS 방문 확인

- 장소 설명의 'GPS 방문 확인하고 방명록 쓰기'를 누르면 04 화면으로 간다.
- 현재 위치와 장소 좌표의 거리가 `visitRadiusMeters` 이하이고 위치가 유효하면 '방문 확인 완료'와 '작성 가능'을 보여준다. 이 화면에서 '아직 도장은 찍히지 않았어요. 공개 업로드가 완료되면 도장이 찍혀요'를 안내한다.
- 범위 밖이거나 권한이 없으면 04-E로 간다. 작성 진입은 막고 초안은 유지한다.
- 측정 시각과 위치 정확도를 검사한다. 허용값은 현장 테스트 후 정한다.
- 서버가 방문 확인 요청과 업로드 요청의 위치 조건을 검증한다. 앱의 '작성 가능' 표시만 믿지 않는다.
- 방문 확인 결과는 DB에 저장하지 않는다. 업로드 때 현재 GPS를 다시 검증한다.
- GPS 조작을 완전히 막는 보안은 MVP 범위 밖이다.

수용 기준: 반경 안에서만 작성·등록이 가능하다. 권한 거부, 오래된 좌표, 정확도 미달, 반경 밖은 방문 확인으로 처리되지 않는다. 장소 선택이나 이미지 인식으로 우회할 수 없다.

### FR-04. 장소 설명·갤러리 열람

- 장소 설명(03): 대표 사진, '푸른캠퍼스 산책 · n번째 장소', 장소명, 소개, 관람 포인트, '여기에 어떤 추억을 남길까요?' 안내, 찾아가는 길과 방문 확인 지점, '장소 갤러리 열기'. 하단에 '공개 업로드에 성공하면 장소 도장을 받아요'와 방문 확인 버튼을 둔다.
- 장소 갤러리(03-A): '장소 설명 보기' 접기·펼치기, '공개된 기록' 2열 카드, '기록 더 보기 · n/전체'. 갤러리에서도 방명록 작성으로 진입할 수 있다.
- 장소 설명과 갤러리는 위치 권한 없이 열람한다. 푸앙이를 탭해서 설명을 여는 흐름은 없다.

수용 기준: 4개 장소의 설명과 갤러리에 접근할 수 있다. 설명을 열람하는 것만으로 방문·도장을 만들지 않는다.

### FR-05. 촬영(AR·일반·갤러리)

- 05 촬영 방식 선택: 'GPS 방문 확인 완료 · 도장 n/4' 칩 아래에서 '푸앙이와 함께 찍기(AR)'와 '일반 사진으로 찍기' 중 하나를 고른다. AR은 지원 기기만, 일반은 호환 기기 모두 쓴다.
- 05-A AR 촬영: 푸앙이를 배치하고 위치·크기를 조정한 뒤 '사진 찍기'. 'AR 촬영 / 일반 사진' 모드 전환과 재배치(화면 길게 누르기)를 제공한다.
- 05-B 일반 사진: 카메라 뷰, 셔터, 갤러리 버튼, 플래시.
- 06 사진 확인: '다시 촬영'과 '갤러리에서 변경'으로 사진을 바꿀 수 있다.
- AR 결과 이미지에는 실제 카메라 배경과 푸앙이가 함께 들어가야 한다. UI 버튼이 사진에 섞이면 안 된다.
- AR은 사진을 찍기 위한 기능이며 장소 판별과 방문 판정에는 쓰지 않는다. 일반 촬영으로 바꿔도 위치 기반 작성 조건은 같다.

수용 기준: 지원 실기기에서 찍은 이미지에 푸앙이가 포함되고, 편집·업로드·재조회 후에도 보인다. AR 미지원 기기와 카메라 권한 거부 상태에서도 앱이 멈추지 않는다.

### FR-06. 꾸미기·공개 업로드

- 작성 단계는 '01 사진 선택 → 02 손그림 → 03 메시지' 순서로 표시한다. 꾸미기는 선택이며 '꾸미지 않고 다음'으로 건너뛸 수 있다.
- 06-A '사진 위에 그리기': 기본 펜, 지우개, 5가지 색상, '글자 추가·선택', '그림만 지우기', '편집 완료'.
- 사진, 손그림, 사진 위 글자는 한 장의 이미지로 합쳐 저장한다. 선택 메시지는 이미지와 별도로 저장한다.
- 07 공개 업로드 화면에는 장소(고정), 작성자 닉네임, 편집한 이미지, '사진·손그림 편집' 링크, 메시지 입력(0\~80자, 선택), 현재 위치 재확인 결과('다시 확인'), 공개 안내, '공개 업로드' 버튼을 둔다.
- 공개 안내 문구: '모두에게 공개. 사진·손그림·선택 메시지와 닉네임이 장소 갤러리와 전체 공개 기록에 보여요.' 공개 범위를 고르는 UI는 없다.
- '공개 업로드'를 누르면 최신 GPS를 다시 확인하고 서버가 위치 조건을 검증한다.
- 저장 중에는 중복 제출을 막는다. 위치 확인이나 저장이 실패해도 초안은 유지하고, 위치를 다시 확인한 뒤 재시도할 수 있다.
- 이미지 저장과 DB 기록이 모두 끝난 뒤에만 성공을 표시하고 도장을 갱신한다.
- 뒤로 가면 작성 내용 폐기 여부를 확인한다.
- 입력 제한(기준안): 메시지 최대 80자, 최종 이미지 JPEG 또는 PNG 최대 10MB.

수용 기준: 사진만, 사진+손그림, 사진+글자, 사진+메시지를 각각 등록할 수 있다. 서버 저장 전에는 도장을 주지 않는다. 같은 `clientRequestId`로 재시도해도 기록이 중복되지 않는다.

### FR-07. 공개 갤러리·기록 상세

- 장소별 공개 기록을 `createdAt DESC, id DESC`로 조회한다. 카드에는 사진, 메시지, 작성자 닉네임, 작성일을 보여준다.
- 빈 상태, 추가 로딩, 실패, 마지막 페이지를 구분한다. 새 기록을 올리면 목록을 갱신하고 중복 ID는 한 번만 보여준다.
- 기록 상세(09-A-1 '추억 보기'): 작성자, 작성일, '이 장소에 공개' 배지, 사진, 메시지, 장소, '○○ 전체 기록' 버튼.
- 타인의 기록에는 수정·삭제·신고가 없다.
- 공개 기록은 로그인한 앱 사용자라면 누구나 열람한다.

수용 기준: 장소 간 기록이 섞이지 않는다. 내가 올린 기록은 다른 계정에서도 보인다. 이미지 한 장이 실패해도 갤러리 열람은 계속된다.

### FR-08. 마이페이지

- 제목은 '○○의 왔다감', 요약은 '공개 n개 · 초안 n개'. 우측 상단에서 설정으로 간다.
- 도장판: '푸른캠퍼스 산책 n/4 도장 수집'과 4개 장소의 도장. 미수집은 잠금 아이콘으로 표시한다.
- 장소 필터(전체, 정문 느티나무길, 중앙도서관, 호수정원, 학생회관)와 장소별 내 기록 목록.
- 기록 카드에는 '이 장소에 공개' 또는 '작성 중' 배지와 작성일을 보여준다. 수정한 기록은 '수정됨'을 붙인다.
- 기록을 누르면 상세로 가고, 거기서 수정·삭제한다.
- 도장 수와 작성 건수를 구분해서 보여준다.

수용 기준: 방문만 한 장소는 도장이 비어 있고 저장을 마친 장소만 채워진다. 같은 장소에 방명록이 여러 건이어도 도장은 하나다. '작성 중' 초안은 공개 갤러리에 보이지 않는다.

### FR-09. 내 기록 수정·삭제 (P1)

- 수정(09-B-1 '공개 방명록 수정'): 장소는 바꿀 수 없다. 사진 교체, 손그림·글 편집, 선택 메시지(0\~80자)를 바꾼다. '변경 사항 저장'과 '취소'를 제공한다.
- 수정한 내용은 장소 갤러리에 반영된다. 수정으로 도장이 추가 지급되지 않고, 카드에 '수정됨'이 붙는다.
- 삭제(09-B-2): '이 추억을 삭제할까요?' 바텀시트에서 '추억 영구 삭제' 또는 '취소하고 추억으로 돌아가기'. 삭제한 기록은 복구할 수 없고 내 목록과 장소 갤러리·전체 공개 기록에서 사라진다. **해당 장소의 방문 도장은 그대로 남는다.**
- 본인 기록만 수정·삭제할 수 있다. 서버가 작성자를 검증한다. 삭제하면 저장된 이미지 파일도 정리한다.

수용 기준: 다른 사람의 기록은 수정·삭제할 수 없다(앱 UI와 API 모두). 삭제 후에도 도장 수와 4칸 도장판이 그대로다. 수정 후 도장 수가 늘지 않는다.

### FR-10. 방명록 기반 도장

- 해당 장소에서 GPS 조건을 충족한 방명록의 저장이 성공하면 도장을 지급한다. 사용자·장소별 1개, 전체 최대 4개.
- 방문 확인, AR·일반 촬영, 편집 완료만으로는 지급하지 않는다. 같은 장소에 다시 올리거나 수정하거나 재시도해도 추가되지 않는다.
- 방명록 생성과 최초 도장 지급은 같은 DB 트랜잭션에서 처리한다.
- 08 성공 화면에 '○○ 도장 획득! n/4'와 '첫 공개 업로드로 받은 도장이에요. 도장은 장소마다 한 번만 지급돼요'를 보여준다.
- 방명록을 삭제해도 도장은 유지한다.

수용 기준: 업로드 실패 시 도장이 없고 성공 후에는 있다. 재로그인해도 유지된다. 4곳에서 각각 저장하면 4개가 된다.

### FR-11. 계정 설정 (로그아웃 P0, 나머지 P1)

- 설정(09-B-3): 닉네임과 '카카오 계정으로 이용 중', '닉네임 수정', 개인정보 안내('이동 경로는 저장하지 않아요. 방문 확인과 업로드 시 현재 위치만 확인해요'), 로그아웃, 회원 탈퇴.
- 회원 탈퇴는 확인 시트에서 '내 기록 n개와 이미지 n장이 영구 삭제돼요'를 보여주고, '동의하고 계정 영구 삭제'를 눌러야 진행한다. 탈퇴하면 모든 기록과 사진·그림이 장소 갤러리에서도 사라지고 복구할 수 없다.
- 로그아웃하면 기기의 서비스 인증 상태를 해제한다.

수용 기준: 탈퇴 후 해당 계정의 방명록·이미지·도장이 남지 않는다. 같은 카카오 계정으로 다시 가입하면 새 계정으로 시작한다.

| 엔티티 | 주요 필드 | 제약 |
| --- | --- | --- |
| User | id, kakaoUserId, nickname, createdAt | kakaoUserId 고유, nickname 2\~10자(한글·영문·숫자), password 필드 없음 |
| Place | id, courseOrder, name, description, highlight, directions, visitPointName, latitude, longitude, visitRadiusMeters (장소 사진은 앱에 포함하며 서버가 내려주지 않음) | 장소 4개. v1.1의 notificationRadiusMeters는 삭제 |

| Draft | id, userId, placeId, image, message, updatedAt | '작성 중' 초안. 저장 위치(기기·서버)는 13절에서 확정. 공개 갤러리와 도장에 영향 없음 |

- `captureType`(AR·일반 촬영 구분)은 v1.2에서 제거했다. 촬영 방식은 작성 자격에 영향을 주지 않는다.
- `updatedAt`이 `createdAt`보다 늦으면 화면에 '수정됨'을 표시한다.
- 생성 시각은 서버 기준 UTC로 저장하고 화면에는 한국 시간으로 표시한다.
- 원시 GPS는 현재 조건 검증에만 쓰고 이동 경로를 저장하지 않는다. 카카오 인증 정보와 좌표는 일반 로그에 남기지 않는다.
- 회원 탈퇴 시 User, GuestbookEntry, Draft, Stamp와 S3 이미지를 모두 삭제한다.
- v1.1의 PlaceNotification 엔티티는 삭제했다.

## 9. API 요구사항

제품 계약의 개요다. 카카오 토큰 검증 방식과 위치 요청 필드의 세부 형식은 구현 명세에서 확정한다. 카카오 인증 진입 API를 제외한 모든 API는 인증을 요구한다.

| 메서드 | 경로 | 입력·결과 |
| --- | --- | --- |
| POST | `/api/auth/kakao` | 카카오 인증 증빙 검증, 사용자 연결, 서비스 세션 발급. 응답에 신규 가입 여부(닉네임 설정 필요)를 포함 |
| POST | `/api/auth/logout` | 서비스 로그아웃 |
| PATCH | `/api/me/nickname` | 닉네임 설정·수정. 길이·문자 규칙 검증 |
| DELETE | `/api/me` | 회원 탈퇴. 기록·이미지·도장·방문 영구 삭제 |
| GET | `/api/places` | 장소 4개, 좌표, 방문 반경, 방명록 존재, 내 도장 상태 |
| GET | `/api/places/{id}` | 소개, 관람 포인트, 찾아가는 길, 방문 확인 지점 |
| POST | `/api/places/{id}/visits` | GPS·정확도·측정 시각 검증. 방문 가능 여부만 응답하고 저장하지 않음 |
| GET | `/api/places/{id}/guestbook?page=&size=` | 공개 방명록 최신순 페이지 |
| POST | `/api/places/{id}/guestbook` | 이미지·선택 메시지·clientRequestId·현재 GPS. 저장과 도장 결과 반환 |
| GET | `/api/guestbook/{id}` | 공개 기록 상세 |
| PATCH | `/api/guestbook/{id}` | 본인 기록 수정(이미지, 메시지). 도장·방문에는 영향 없음 |
| DELETE | `/api/guestbook/{id}` | 본인 기록 영구 삭제. 도장 유지 |
| GET | `/api/me/guestbook?page=&size=` | 내가 올린 공개 기록(장소 필터 가능) |
| GET | `/api/me/stamps` | 장소별 도장 4칸, 획득 수 |

v1.1의 `/api/places/{id}/proximity-notifications`와 `/api/me/proximity-notifications` 3종은 삭제했다.

### 9.1 공통 처리

- 작성자, 방문자, 도장 소유자는 인증 정보에서 결정한다.
- 방명록 등록 요청의 현재 GPS를 과거 방문 이력과 별개로 검증한다.
- 수정·삭제는 기록 작성자만 할 수 있다. 다른 사람의 기록이면 거부한다.
- 페이지 기본 크기는 20, 최대 50(기준안).
- 인증 실패, 위치 확인 실패, 반경 밖, 크기 초과, 통신·저장 실패를 구분해서 응답한다.
- 방명록 재시도는 같은 `clientRequestId`를 사용하고, 기존 성공 결과를 반환한다.
- 이미지 저장 후 DB 처리가 실패하면 고아 이미지를 정리한다. 기록 삭제·회원 탈퇴 때도 이미지를 정리한다.
- 방명록과 최초 도장은 함께 확정한다. 둘 중 하나만 성공한 상태를 남기지 않는다.

## 10. 기술·비기능 요구사항

### 10.1 구성 방향

기술 스택은 Figma 발표 자료(Wattagam Proposal)의 요구사항 슬라이드를 따른다.

```
Android 앱: Kotlin, Jetpack Compose
  - 카카오 로그인, 닉네임, 위치 권한
  - 안내 지도, GPS 방문 확인
  - CameraX 촬영, 푸앙이 AR 촬영(ARCore / SceneView)
  - 손그림·글자 편집(Compose Canvas)
  - 공개 방명록, 도장판, 내 기록 관리
            |
      HTTPS 서비스 API (Retrofit)
            |
Spring Boot 서버 (Kotlin)
  - 카카오 인증 검증, JWT 세션
  - 방문·등록 위치 검증
  - 방명록·도장 트랜잭션, 수정·삭제·탈퇴 처리
  - MySQL 데이터, S3 이미지
```

지도 SDK, Android 지원 버전, AR·카메라 라이브러리 버전은 기술 검증 후 확정한다. 촬영 방식은 푸앙이가 최종 이미지에 실제로 포함되는지를 기준으로 고른다.

### 10.2 품질과 운영

| 항목 | 요구사항 |
| --- | --- |
| 안정성 | 핵심 흐름을 반복해도 강제 종료, 기록 유실, 중복 도장이 없어야 한다. |
| 응답성 | 정상 네트워크에서 장소·설명·갤러리 첫 결과 3초 이내를 목표로 둔다. 측정 조건을 함께 기록한다. |
| 권한 | 위치·카메라 권한을 기능 목적과 함께 요청하고, 거부 상태를 구분해서 안내한다. 알림 권한은 요청하지 않는다. |
| 위치 | 앱을 사용하는 동안에만 위치를 쓴다. 백그라운드 위치 감시는 하지 않는다. |
| 배터리 | 카메라는 화면을 벗어나면 해제한다. |
| 보안 | 배포 API에 HTTPS를 적용하고 토큰·스토리지 비밀키를 소스와 로그에 노출하지 않는다. |
| 이미지 | AR 캐릭터와 손그림·글자가 최종 이미지에 포함되어야 한다. 불필요한 EXIF 위치정보를 제거한다. |
| 공개 안내 | 업로드 전에 사진·메시지·닉네임·작성 시각이 앱 사용자에게 공개됨을 안내한다. |
| 삭제 | 기록 삭제와 회원 탈퇴는 DB와 이미지 저장소에서 함께 지운다. |
| 운영 | 제한된 과제 시연으로 시작한다. 시연 후 보관 종료일과 정리 담당을 정한다. |

공개 서비스 전의 콘텐츠·캐릭터 사용 조건 검토는 별도로 정한다.

- [ ] AR 푸앙이가 포함된 사진 저장·재조회 완료
- [ ] 방명록 성공 기반 도장 4개 수집 검증
- [ ] 타 계정에서 공개 기록 조회, 나만 보기 기능 부재 확인
- [ ] 내 기록 수정·삭제와 도장 유지 확인
- [ ] 회원 탈퇴 후 데이터 삭제 확인
- [ ] 재실행·재로그인 후 방명록·도장 복원
- [ ] 필수 QA 결과, 시연 영상, 배포본 준비

### 12.2 6주 기준 계획

주차별 마일스톤 이름(3·4·6주차)은 발표 자료의 로드맵을 따랐다. 알림 작업은 4주차에서 빼고 수정·삭제·탈퇴로 바꿨다.

| 주차 | 주요 작업 | 완료 조건 |
| --- | --- | --- |
| 1주차 | 카카오 설정, 장소 좌표·방문 반경 정책, 기기·AR 캡처 검증 | 카카오 로그인·GPS·AR 사진 각각의 실기기 가능 여부 확인 |
| 2주차 | 지도 4곳·설명, 인증·닉네임 API, 위치 검증, 촬영·꾸미기 | 로그인 후 현장 조건으로 촬영·꾸미기 진입 |
| 3주차 | 공개 등록, 갤러리, 도장 원자적 지급 | 한 장소에서 등록·조회·도장까지 성공 (Save and reload) |
| 4주차 | 마이페이지, 내 기록 수정·삭제, 권한·초안 처리, P0 통합 | 핵심 흐름 검증 (Validate the core flow) |
| 5주차 | AR 촬영 통합, 회원 탈퇴, 4곳 현장 검증 | 푸앙이 포함 사진 저장, 4개 도장 수집 |
| 6주차 | 오류 복구, 사용자 테스트, 시연 | 필수 QA 통과와 결과 기록 (Live campus demo with AR) |

실제 착수일과 제출일은 미정이다. 진행 상황에 따라 남은 작업을 다시 배정한다.

### 12.3 주요 리스크

| 리스크 | 대응 |
| --- | --- |
| GPS 오차로 방문 판정 오류 | 첫 주 현장 측정, 정확도·유효 시간 확정, 불확실하면 도착을 단정하지 않는다 |
| AR 화면과 결과 사진 불일치 | 모델 포함 캡처를 먼저 검증하고 업로드 후 이미지까지 확인한다 |
| 방명록 실패에도 도장 생성 | 방명록과 최초 도장을 한 트랜잭션으로 묶고 `clientRequestId`로 재시도를 구분한다 |
| 카카오 인증 설정·계정 연결 오류 | 첫 주 로그인 검증, 외부 식별자 기반 계정 연결 |
| 위치 조건이 작성 도중 바뀜 | 초안 유지, 등록 전 재검증, 현장 복귀 안내 |
| 삭제·탈퇴 후 이미지나 데이터가 남음 | 삭제 시 DB와 S3를 함께 정리하고 QA-16·QA-19로 확인한다 |
| 다른 사람의 기록을 수정·삭제 | 서버에서 작성자를 검증하고 QA-17로 확인한다 |
| 일정 부족 | 위치·공개 등록·도장을 우선하고, 고급 AR 연출·편집 도구·회원 탈퇴를 줄인다 |

## 13. 결정이 필요한 사항과 Figma 정리 항목

확정된 카카오 단독 로그인, 4개 장소, GPS 방문, 방명록 기반 도장, 촬영용 AR, 전체 공개, 알림 삭제는 아래 항목으로 되돌리지 않는다.

### 13.1 결정이 필요한 세부 정책

| 항목 | 현재 기준안 | 확정할 내용 |
| --- | --- | --- |
| 초안 저장 위치 | 마이페이지에 '작성 중' 초안을 표시 | 기기 로컬 저장인지 서버 저장인지. 앱 재설치·다른 기기 복원 범위 |
| 갤러리에서 고른 사진 | 업로드 가능(GPS 조건은 동일) | 현장에서 찍지 않은 사진을 허용하는 것이 의도인지 |
| 수정 시 위치 확인 | 미정 | 사진 교체·수정 저장 때 현재 GPS를 다시 확인할지 |
| 방문 반경 | 기존 30m 임시 유지 | 장소별 반경, GPS 정확도·유효 시간 기준 |
| 지도 방식 | 일러스트형 안내 약도, 핀·목록 선택 | 지도 SDK 사용 여부, 현재 위치 표시 여부 |
| 닉네임 규칙 | 2\~10자, 한글·영문·숫자 | 중복 허용 여부, 닉네임 변경 시 기존 기록의 표시명 반영 |
| 카메라 권한 거부 | 촬영 불가 | 갤러리 선택만으로 작성을 이어갈지 |
| 장소 세부 데이터 | 4곳 이름·소개·관람 포인트·길 안내는 Figma 문구 | 기준 좌표, 대표 사진 사용 허가, 공식 장소명 |
| 회원 탈퇴 | 모든 기록·이미지 즉시 영구 삭제 | 유예 기간 필요 여부, 탈퇴 후 재가입 정책 |
| 일정·운영 | 4인·6주 기준 | 제출일, 시연 방식, 보관 종료일, 삭제 담당 |

### 13.2 Figma 쪽에서 정리가 필요한 항목

전체공개와 알림 삭제 결정 이후에도 Figma에 이전 안의 흔적이 남아 있다. 개발자가 잘못 구현하지 않도록 정리를 권한다.

- 'Taste 제안' 프레임(2026-11-01)의 추억 남기기 화면에 '나만 보기' 선택지와 '공개 범위' 영역이 있다.
- 같은 프레임의 홈·코스 지도 화면은 '세 장소' 코스와 방문 0/3 기준이며, 현재 4곳 흐름과 다르다.
- '이전 안 · 참고용' 섹션에 직접 작성, 게스트 로그인, 마커 보드, 인식된 추억 보드 화면이 남아 있다. 현재 1\~10단계 흐름에서는 제외된 화면이다.
- 마이페이지의 두 번째 카드는 컴포넌트 이름이 '비공개 사진 기록'이지만 화면에는 '작성 중' 배지로 표시된다. 초안임을 이름에서도 구분하는 편이 좋다. 또한 추억 보기(09-A-1)의 '신고' 버튼은 신고 기능 제외에 따라 Figma에서 삭제한다.
- 09-B-1 수정 화면에 숨겨진 공개 범위 선택 항목이 하나 더 있다. 삭제하는 편이 좋다.
- 발표 자료 03번 슬라이드의 폰 예시 화면은 '푸앙이 장소 설명 듣기·추억 보드 열기' 등 이전 흐름을 보여준다.

## 14. 용어

| 용어 | 정의 |
| --- | --- |
| 푸른캠퍼스 산책 | 4개 장소로 이루어진 투어 코스 이름 |
| 투어 장소 | 정문 느티나무길, 중앙도서관, 호수정원, 학생회관 중 하나 |
| 방문 확인 | 현재 GPS가 방문 반경 조건을 충족한 상태 |
| 작성 자격 | 작성 시작·업로드 때 현재 GPS로 확인한 현장 조건 |
| 방명록(추억) | 사진, 손그림, 글자, 선택 메시지로 이루어진 공개 기록 |
| 초안(작성 중) | 아직 올리지 않은 방명록. 공개 갤러리와 도장에 영향이 없다 |
| 도장 | 현장에서 방명록 저장에 성공한 장소의 수집 표시. 장소마다 한 번, 삭제해도 유지 |
| AR 촬영 | 실제 카메라 배경과 푸앙이를 함께 이미지로 저장하는 기능 |
| 이미지 인식 | 사진·마커로 장소를 식별하는 기능. 사용하지 않음 |
| 내 방명록 | 본인이 작성한 공개 기록의 모아보기 |
